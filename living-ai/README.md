# LIVING AI — จิ๋ว 🤖

AI Companion บน Android ที่ **มองเห็นหน้าจอ เข้าใจสิ่งที่เห็น และช่วยกดแทนผู้ใช้ได้จริง**
ตัวละครคือ "จิ๋ว" หุ่นยนต์จิ๋วที่ลอยอยู่บนจอ

เป้าหมายอุปกรณ์: Samsung Galaxy A07 4G (Android 16, RAM 4 GB, Helio G99) · `minSdk 26` · `targetSdk 36`

> เอกสารนี้แยกชัดเจนว่าอะไร **ทดสอบแล้ว** และอะไร **ยังไม่ได้ทดสอบ** ดูหัวข้อ [สถานะการทดสอบ](#สถานะการทดสอบ)

## 1. ผลตรวจสอบความเป็นไปได้ (API และข้อจำกัดจริงของ Android)

| ความต้องการ | ทำได้ไหม | วิธี / ข้อจำกัดจริง |
|---|---|---|
| อ่านข้อความ ปุ่ม เมนูของแอปอื่น | ✅ | `AccessibilityService` + node tree ได้ข้อความตรงตัวทุกภาษา (รวมไทย) แทบไม่กินทรัพยากร จึงใช้เป็น "ตา" หลัก |
| เห็นภาพหน้าจอ (เกม วิดีโอ รูป) | ✅ มีเงื่อนไข | `MediaProjection` ผู้ใช้ต้องกดยอมรับ **ทุกครั้งที่เริ่ม** (token ใช้ได้ครั้งเดียว), ต้องรันใน Foreground Service ชนิด `mediaProjection` (Android 14+), ระบบ **หยุดให้เองเมื่อล็อกจอ** (Android 15+) และแสดงชิปบนแถบสถานะ |
| OCR ในเครื่อง | ⚠️ บางส่วน | ML Kit Text Recognition v2 **ไม่มีโมเดลภาษาไทย** (มี Latin/จีน/เทวนาครี/ญี่ปุ่น/เกาหลี) จึงใช้ OCR เฉพาะตัวอักษรละติน ข้อความไทยได้จาก node tree หรือให้ Vision LLM อ่านจากภาพ |
| แตะ / พิมพ์ / เลื่อน / ย้อนกลับ | ✅ | `performAction` บนโหนดจริง, `dispatchGesture` เป็นทางสำรอง (แตะ "กลางขอบเขตขององค์ประกอบที่ตรวจพบ" เท่านั้น ไม่มีพิกัดสุ่ม) |
| เปิดใช้ Accessibility | ✅ ผู้ใช้เปิดเอง | APK ที่ติดตั้งนอก Play Store ติด **Restricted settings** (Android 13+): ต้องไป ข้อมูลแอป → ⋮ → "อนุญาตการตั้งค่าที่ถูกจำกัด" ก่อน |
| หน้าจอ `FLAG_SECURE` / DRM | ❌ โดยเจตนา | ภาพที่ได้เป็นสีดำ ระบบตรวจจับแล้วแจ้งว่า "ถูกป้องกัน" **ไม่พยายามหลบเลี่ยง** |
| แอปที่ซ่อนข้อมูลจาก accessibility ที่ไม่ใช่เครื่องมือช่วยการเข้าถึง | ❌ โดยเจตนา | ประกาศ `isAccessibilityTool="false"` ตามจริง แอปธนาคารบางตัวจะไม่ส่งข้อมูลให้ |
| มองแบบ "เรียลไทม์ตลอดเวลา" | ❌ ไม่เหมาะกับ RAM 4 GB | ใช้ event-based แทน: มองเมื่อผู้ใช้สั่ง เมื่อสลับแอป หรือเมื่อพบข้อความผิดพลาด |

### เอเจนต์ทั้งสี่

| เอเจนต์ | หน้าที่ | ไฟล์ |
|---|---|---|
| **Main AI** | เข้าใจคำสั่ง ตัดสินใจ สนทนา ประสานเอเจนต์อื่นผ่านเครื่องมือ `observe_screen` `tap` `type_text` `scroll` `press_key` `open_app` `wait` `remember` `recall` | `core/agent/MainAgent.kt` |
| **Vision AI** | รวม node tree + OCR + ภาพย่อ เป็น `ScreenObservation` ที่ลบข้อมูลลับแล้ว ขอภาพเฉพาะเมื่อข้อความบนจอน้อย | `core/agent/VisionAgent.kt`, `app/vision/*` |
| **Action AI** | ตรวจว่า id มีอยู่จริงบนจอล่าสุด → ผ่านนโยบายความปลอดภัย → ขอยืนยัน → ลงมือ → มองซ้ำแล้วเทียบว่าหน้าจอเปลี่ยนหรือไม่ | `core/agent/ActionAgent.kt`, `app/control/*` |
| **Memory AI** | จำสิ่งที่ผู้ใช้บอก เหตุการณ์ล่าสุด และบทสนทนา ใส่เป็นบริบทให้ทุกเซสชัน | `core/agent/MemoryAgent.kt`, `app/data/MemoryDb.kt` |

"Vision AI API" และ "LLM API" ใช้โมเดล Claude ตัวเดียวกัน (อ่านภาพได้ในตัว) ผ่าน SDK ทางการ `com.anthropic:anthropic-java`
ค่าเริ่มต้น `claude-opus-5-5` ที่ effort `low` (ตอบไว) เปลี่ยนเป็น Sonnet/Haiku ได้ในหน้าตั้งค่า

### เป้าหมายการกดมาจากองค์ประกอบจริงเสมอ

1. `NodeSnapshot` เก็บ id → `AccessibilityNodeInfo` จริงของหน้าจอ ณ เวลานั้น
2. โมเดล/ผู้ใช้อ้างได้เฉพาะ `element_id` ไม่มีเครื่องมือกดด้วยพิกัด
3. ก่อนทำ: ตรวจว่า observation ยังเป็นชุดเดียวกับ snapshot (เทียบ timestamp) และ `node.refresh()` ยังสำเร็จ
4. หลังทำ: มองใหม่และเทียบลายเซ็นหน้าจอ รายงานตามจริงว่า "เปลี่ยน" หรือ "ไม่เปลี่ยน"

## 4. ระบบความปลอดภัย

| ข้อกำหนด | การทำงานจริง |
|---|---|
| ขออนุญาต Screen Capture | กล่องยืนยันของระบบทุกครั้ง; แจ้งเตือนถาวรพร้อมปุ่ม "หยุดมองหน้าจอ" / "หยุดทุกอย่าง" |
| ผู้ใช้เปิด Accessibility เอง | แอปทำได้แค่พาไปหน้าตั้งค่า |
| ไม่ดักรหัสผ่าน/PIN/OTP | ช่อง `isPassword` ไม่ถูกอ่าน; หน้าที่มีช่องรหัสผ่าน หรือมีคำว่า OTP/PIN คู่กับช่องกรอก → ลบทั้งหน้า (ไม่มีข้อความ ไม่มีภาพ ไม่มีเป้าหมายให้กด) **ตัดสินจาก node tree ก่อนจับภาพ**; เลข OTP ใน SMS และเลขบัตรถูกแทนด้วย `•••`; ถ้ามีบริบท OTP จะไม่ส่งภาพ |
| ไม่ทำธุรกรรม/ส่ง/ซื้อ/ลบโดยไม่ยืนยัน | `SafetyPolicy` ทำงานในโค้ดแอป **หลัง** โมเดลตัดสินใจ: ปุ่มที่มีคำว่า ส่ง/ซื้อ/จ่าย/โอน/ลบ/ยืนยัน/อนุญาต ฯลฯ (รวมชื่อ view id เช่น `send_button`) และทุกการกดในแอปการเงิน ต้องกด "อนุญาต" บนจอก่อน หมดเวลา 30 วินาที = ไม่อนุญาต |
| หน้าจอระบบที่ป้องกัน | หน้าขอสิทธิ์ ตัวติดตั้งแพ็กเกจ และ keyguard ถูกระงับการควบคุมทั้งหมด |
| FLAG_SECURE | ภาพดำ → แจ้ง `protectedContent` ไม่พยายามหลบเลี่ยง |
| ปุ่มหยุดทันที | แตะหุ่นยนต์ขณะทำงาน · ปุ่ม ⏹ ในแผงคำสั่ง · ปุ่มแดงในแอป · ปุ่มในแจ้งเตือน (หยุดฉุกเฉิน = ยกเลิกงาน + หยุดจับภาพ + ไม่มอง/ไม่กดจนกว่าจะกด "ทำงานต่อ") |
| แสดงสถานะ | สีตาและป้ายใต้หุ่นยนต์: 👁 กำลังมอง · 💭 กำลังคิด · ✋ กำลังควบคุม · ❓ รอยืนยัน · ⏸ หยุดอยู่ |
| ข้อความบนจอไม่ใช่คำสั่ง | system prompt กำหนดให้ถือเป็นข้อมูล (กัน prompt injection จากเนื้อหาบนจอ) และนโยบายยืนยันยังบังคับซ้ำในโค้ด |
| API key | เข้ารหัส AES-GCM ด้วยกุญแจใน Android Keystore; `allowBackup=false` |

## 5. การประหยัดทรัพยากร (RAM 4 GB)

- **ไม่มี timer** — ทำงานเมื่อมีเหตุการณ์เท่านั้น; อีเวนต์ accessibility ถูก throttle 300 ms และ handler ทำแค่จำชื่อแพ็กเกจ
- node tree ก่อนเสมอ; จับภาพเฉพาะเมื่อข้อความบนจอน้อยหรือโมเดลขอ
- `VirtualDisplay` **ไม่มี surface ขณะว่าง** (ระบบไม่ต้อง compose ให้) ติด surface เฉพาะตอนขอเฟรม แล้วถอดออกใน 4 วินาที
- จับภาพที่ขอบสั้น ~540 px, ถือเฟรมในหน่วยความจำไม่เกิน 1 เฟรม, ภาพที่ส่ง AI ย่อเหลือ ≤ 768 px JPEG คุณภาพ 60
- OCR รันเฉพาะเมื่อภาพเปลี่ยนจริง (`FrameDiff`)
- โหมดเกม: ตรวจจาก `ApplicationInfo.CATEGORY_GAME` → คืนหน่วยความจำ capture/OCR, ปิดการเฝ้าข้อผิดพลาด, ช่วงพักการพูดเอง 10 นาที
- `onTrimMemory`: ปิดตัวรู้จำ OCR, ปล่อยเฟรม, ปล่อย HTTP client, งดพูดเอง 90 วินาที
- UI เป็น View ของเฟรมเวิร์กล้วน (ไม่มี Compose/AppCompat)

## 6. Build

ต้องใช้ JDK 17+ และ Android SDK (platform 36)

```bash
cd living-ai
./gradlew :core:test            # unit test ของเอเจนต์/ความปลอดภัย
./gradlew :app:assembleDebug    # → app/build/outputs/apk/debug/app-debug.apk
```

เครื่องที่ไม่มี Android SDK / เข้า Google Maven ไม่ได้ ยังตรวจได้บางส่วน:

```bash
./gradlew :core:test :typecheck:compileKotlin -PcoreOnly=true
```

ทุกครั้งที่ push, GitHub Actions (`LIVING AI (Android)`) จะ build APK (ดาวน์โหลดจาก Artifacts ชื่อ `living-ai-debug-apk`)
และรันเทสต์บนอีมูเลเตอร์ Android 16

## 7. วิธีทดสอบบน Android 16 (เครื่องจริง)

1. ติดตั้ง `app-debug.apk` (อนุญาต "ติดตั้งแอปที่ไม่รู้จัก" ให้ตัวจัดการไฟล์/เบราว์เซอร์)
2. เปิด **LIVING AI** → กด **ขออนุญาต** ที่ "การแจ้งเตือน"
3. Accessibility: กด **เปิดการตั้งค่า** → แอปที่ติดตั้ง → *LIVING AI — จิ๋ว* → เปิด
   - ถ้าเป็นสีเทา/ขึ้น "การตั้งค่าที่ถูกจำกัด": กลับมากดปุ่ม **เปิดหน้าข้อมูลแอป** → ⋮ มุมขวาบน → **อนุญาตการตั้งค่าที่ถูกจำกัด** → ยืนยันด้วย PIN แล้วลองใหม่
   - หุ่นยนต์จิ๋วจะลอยขึ้นมาบนจอ
4. Screen Capture: กด **เริ่ม** → เลือก "ทั้งหน้าจอ" → เริ่ม (จุดสถานะเป็นสีเขียว และมีแจ้งเตือนถาวร)
5. **ทดสอบการมองเห็น**: กด "👁 มองหน้าจอในอีก 4 วินาที" แล้วสลับไปแอปอื่น (เช่น การตั้งค่า, YouTube, เกม) กลับมาดูรายการองค์ประกอบ/OCR/ภาพที่จิ๋วเห็น
6. **ทดสอบการควบคุม (ไม่ต้องมี API key)**: เปิดแอป "การตั้งค่า" → แตะหุ่นยนต์ → พิมพ์
   `ดูหน้าจอ` · `เลื่อนลง` · `กด การเชื่อมต่อ` · `กลับ` · `เปิด YouTube` · `โฮม`
7. **ทดสอบความปลอดภัย**
   - เปิดหน้าล็อกอินที่มีช่องรหัสผ่าน → `ดูหน้าจอ` ต้องตอบว่าเป็นหน้าจอข้อมูลลับ และ `กด …` ต้องถูกระงับ
   - เปิดแอปแชต พิมพ์ข้อความค้างไว้ → `กด ส่ง` ต้องมีกล่อง "จิ๋วขออนุญาต"; กด "ไม่อนุญาต" แล้วข้อความต้องไม่ถูกส่ง
   - เปิดแอปธนาคาร/หน้าจอ FLAG_SECURE → การทดสอบการมองเห็นต้องแสดง `protected=true` หรือไม่มีภาพ
   - ระหว่างจิ๋วทำงานหลายขั้น แตะหุ่นยนต์ → ต้องหยุดทันที; กดปุ่มแดงในแอป → จุด Screen Capture กลับเป็นสีส้ม
8. **ทดสอบ AI เต็มรูปแบบ**: ใส่ Anthropic API key → สั่งงานหลายขั้น เช่น "เปิดการตั้งค่าแล้วพาไปหน้าความสว่างจอ", "วิดีโอนี้เกี่ยวกับอะไร", "ช่วยร่างข้อความตอบว่าเดี๋ยวโทรกลับ"
9. **ทดสอบทรัพยากร**: `adb shell dumpsys meminfo com.livingai.companion` ขณะว่าง/ขณะทำงาน และเปิดเกมเพื่อดูว่าจิ๋วเงียบและคืนหน่วยความจำ
10. ล็อกจอแล้วปลดล็อก → Android 15+ จะหยุด Screen Capture เอง (จุดเป็นสีส้ม) ต้องกด **เริ่ม** ใหม่ — เป็นพฤติกรรมของระบบ

เทสต์อัตโนมัติบนเครื่อง/อีมูเลเตอร์: `./gradlew :app:connectedDebugAndroidTest`

## ข้อจำกัดที่ทราบ / งานถัดไป

- ไม่มี OCR ภาษาไทยในเครื่อง (ข้อจำกัดของ ML Kit) — ข้อความไทยในเกม/วิดีโอต้องพึ่ง Vision LLM
- ยังไม่มีเสียง (พูด/ฟัง) — ต่อยอดได้ด้วย `TextToSpeech` / `SpeechRecognizer`
- ยังไม่ได้เปิด refusal fallback ฝั่งเซิร์ฟเวอร์ของ Claude API; ถ้าโมเดลปฏิเสธ จิ๋วจะแจ้งว่าช่วยไม่ได้
- แชตในหน้าแอปทำกับหน้าจอของแอปเอง ถ้าจะสั่งงานในแอปอื่นให้ใช้หุ่นยนต์ลอย
- APK เป็น debug build (ยังไม่ย่อด้วย R8, เซ็นด้วย debug key) เหมาะสำหรับทดสอบ ไม่ใช่เผยแพร่
- แอปที่เผยแพร่บน Play Store และใช้ AccessibilityService ต้องผ่านนโยบาย/แบบประกาศของ Google เพิ่มเติม
